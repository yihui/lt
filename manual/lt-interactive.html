Description

Make a table interactive in the browser: pagination, a table-wide search box, click-to-sort column headers, per-column filter boxes, and resizable columns. The features are handled client-side by an opt-in JavaScript extension, loaded only for tables that call this function.

Usage

lt_interactive(
  x,
  sort = TRUE,
  search = TRUE,
  filter = "auto",
  pager = c(10, 25, 50, Inf),
  resize = TRUE,
  hide = NULL,
  detail = NULL,
  profile = FALSE,
  download = FALSE
)

Arguments

x

An lt() object.

sort

Whether clicking a column header sorts the table by that column (cycling ascending, descending, then unsorted); shift-clicking adds a column as a further tie-breaker, so several columns can sort at once. Sorting uses the raw values, so numeric columns sort numerically and dates and date-times chronologically. Can also request an initial sort by one or more columns, given either as a character vector of column names or as a one-sided formula (e.g. ~ x + -y); a name prefixed with - (or a negated formula term) sorts that column descending, e.g. c('g', '-x') or ~ g + -x.

search

Whether to show a table-wide search box. A row is kept when any cell matches the term. Besides plain substring matching, a term that references the cell variable x (e.g. x > 5 or x != "A") is evaluated as a JavaScript expression against each cell's value.

filter

The per-column filters. TRUE shows a filter box under every column header, matching terms the same way as search but against that column only (a row is kept when it passes every filter and the search). A character vector of column names restricts the boxes to those columns. A named list gives each named column its own filter: TRUE for a plain box, "select" for a value dropdown, "range" for a two-thumb range slider, or "checklist" for a popover of checkboxes that keeps the rows whose value is checked (the dropdown's / checklist's choices and the slider's ends are taken from the column's data). For a custom label or hand-set options, pass a list instead of the string, e.g. list(type = "select", label = "Cylinders") or list(type = "range", min = 0, max = 100). One unnamed entry in the list is the default applied to every other visible column, so list(TRUE, cyl = "select") boxes every column but gives cyl a dropdown, and FALSE leaves a column without a filter, e.g. list("auto", id = FALSE); set on a named column, it shows a disabled (inert) funnel, so the column reads as filterable but off. A column with nothing to filter (every value blank) gets no box, even under that default. "auto" (alone, or as a list entry, e.g. list("auto", cyl = "select")) picks each column's filter from its data: a range slider for numbers and for dates and date-times (a search-only funnel if every value is the same; a date filter expression compares text, e.g. x >= "2024-01-05"), a checklist for text with at most 10 distinct values, and a search-only funnel otherwise. A typed filter renders as a funnel + popover (holding the widget and an expression box, kept in sync) under its column header, or — when the column is hidden from the table (e.g. with lt_hide()) — as a chip in the control bar, a natural way to offer a control for a value you don't show. Add box = FALSE to a typed spec's list to drop the expression box, restricting the column to the widget's own choices (e.g. a single-select dropdown with no custom set). The widget hides itself whenever a hand-typed expression outruns it (a value it cannot represent), so it never shows a value out of step with the box.

pager

The page sizes to offer, as a vector of row counts; the first one is used initially. Paging shows that many of the filtered and sorted rows at a time, with a pager (first, previous, next, last), the row range, and (for more than one size) a selector below the table. Inf is a valid size (every row on one page), offered as an infinity symbol in the selector. The selector is omitted when the table has no more rows than the smallest page size (no size would split it), though the pager's nav and row-count readout stay, the latter being useful as a filter narrows the rows. Use FALSE or NULL to show all rows with no pager at all.

resize

Whether to let the reader drag a column's right edge to resize it (double-clicking the edge fits the column to its content). Widening a column widens the table, leaving the other columns as they are. Initial widths can be set with lt_width().

hide

Column-visibility control: an eye button in the control bar opens a checklist of every column, where unchecking a column hides it (header and cells) and re-checking restores it. NA adds the menu with all columns shown; column names (a character vector or a one-sided formula, e.g. ~ x + y) adds it with those columns hidden to begin with (every column is still listed, so any can be toggled). To label the button instead of showing the eye icon, use a list with label (a string, shown as a chip in the control bar) and optionally columns (the columns hidden to begin with), e.g. list(label = "Show/Hide columns"). NULL (the default) adds no menu.

detail

Row detail (drill-down). An expand caret is added to each row; clicking it reveals a table built from that row below it. Give the columns to show, as a character vector of names or a one-sided formula (e.g. ~ gear + carb); their displayed (formatted) values are laid out as a one-row table. The columns can be ones hidden from the main table with lt_hide(), a natural way to tuck extra fields into the detail. For full control, pass a JavaScript callback instead, wrapped in js(): it is called as (row, index, display) — row the raw values, display the formatted text, each keyed by column name — and returns a table spec, which may carry its own interactive field to make the detail table interactive. NULL (the default) adds no row detail.

profile

Whether to show a profile of each column: a mini bar chart of its values (a histogram of up to 10 bins for numbers, dates, and date-times; one bar per category for text, left blank if over half of the values are distinct). Hovering over it shows summary statistics (min, max, and mean, or the number of distinct values and the most frequent ones) and the amount of missing values. When the filters keep only some rows, the bars highlight their share. TRUE or "header" puts the chart in the column header; "filter" puts it at the top of the column's filter popover instead, which saves header space (only columns with a popover filter, e.g., the range slider or checklist of filter = "auto", get a profile then).

download

Whether to add a button that downloads the table. The file holds the current view (every row the filters and search keep, in sort order, across all pages) of the table's columns, with the title, column spanners, and notes of formats that have room for them. The button opens a menu of the available formats (CSV and RTF); with a single format, it downloads directly. TRUE adds the button with a default file name; a string sets the file name (a format extension in it is replaced by the chosen format's). For more control, pass a list with any of file (the file name), formats (which formats to offer, e.g., "rtf"; all by default), and mode: "display" (the default) exports the displayed cell text, while "raw" exports the underlying unformatted values (full precision, no thousands separators or percent signs), handier to re-import for analysis. Row detail (detail) is never included. FALSE (the default) adds no button. To save a table to a file from R instead, use lt_export().

Details

Sorting and filtering respect the row structure, happening within each group or subtree rather than across it. Separator row groups (lt_group() with sep = TRUE, or manual groups) keep their order, and a group whose rows all filter out drops its header. Indentation (lt_indent()) sorts siblings under each parent, and an indented child keeps its ancestors visible for context. Rowspan row groups (lt_group() with its default rowspan rendering) sort and filter within each run and clicking a group header reorders its blocks; with several group columns the view stays nested (an inner column reorders only within its parent block), and the spanning cells are redrawn to match.

Value

x with interactivity enabled.

Examples

lt(head(mtcars)) |> lt_interactive()
# search only, no click-to-sort or pagination
lt(head(mtcars)) |> lt_interactive(sort = FALSE, pager = FALSE)
# 5 rows at a time, or all of them, with a filter box on one column
lt(mtcars) |> lt_interactive(filter = 'cyl', pager = c(5, Inf))
# filters are on by default, a widget per column chosen from its data
# (sliders, checklists, boxes); filter = FALSE turns them off
lt(iris) |> lt_interactive(filter = FALSE)
# fixed (non-resizable) columns
lt(head(mtcars)) |> lt_interactive(resize = FALSE)
# a column-visibility menu (all columns shown, or with some hidden to start)
lt(head(mtcars)) |> lt_interactive(hide = NA)
lt(head(mtcars)) |> lt_interactive(hide = ~ hp + drat)
# a labeled button instead of the eye icon
lt(head(mtcars)) |> lt_interactive(hide = list(label = 'Show/Hide columns'))
# an initial sort by cyl, then mpg descending within each
lt(mtcars) |> lt_interactive(sort = ~ cyl + -mpg)
# expandable row detail (drill-down): name the columns to show. Here gear and
# carb are hidden from the main table but revealed in the detail that appears
# when a row is expanded.
lt(head(mtcars)) |>
  lt_hide(~ gear + carb) |>
  lt_interactive(detail = ~ gear + carb)
# for full control, pass a JavaScript callback yourself: (raw row, index,
# displayed row); here showing the row number and mpg as the table displays it
lt(head(mtcars)) |> lt_interactive(
  detail = js('(row, i, d) => ({ data: { metric: ["row", "mpg"],
    value: [i, d.mpg] } })')
)
# a distribution plot in each column header, or in the filter popover
lt(iris) |> lt_interactive(profile = TRUE)
lt(iris) |> lt_interactive(profile = 'filter')
# a button to download the current view as a CSV or RTF file
lt(head(mtcars)) |> lt_interactive(download = TRUE)
lt(head(mtcars)) |> lt_interactive(download = 'cars')
# offer only RTF, which downloads directly
lt(head(mtcars)) |> lt_interactive(download = list(formats = 'rtf'))
# export the raw (unformatted) values instead of the displayed text
lt(head(mtcars)) |> lt_interactive(download = list(file = 'cars.csv', mode = 'raw'))
