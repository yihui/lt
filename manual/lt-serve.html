Serve the rows of an interactive table from a data server

  • Description
  • Usage
  • Arguments
  • Value
  • Examples

Description

Make an interactive table fetch its rows from a URL instead of holding them in the page, for data too big for the browser: whenever the sort, filters, search, or page change, the browser asks the server for just the current page. By default the rows of x are served by a local app built on xfun::new_app() (until xfun::stop_app()); pass url to use your own server instead. Row groups, indentation, and row-specific styles and footnotes are not supported. In a Shiny app, return the table from render_lt() and the rows are served by the session itself (no local app is started). See the examples in the package site for details and the request/response format a custom server implements.

Usage

lt_serve(
  x,
  url = NULL,
  times = NULL,
  cols = NULL,
  n = NULL,
  name = "lt-server",
  ...
)

Arguments

x

An lt_tbl object, typically made by lt_viewer() or lt_interactive(); it is made interactive with the defaults if not yet.

url

The URL of a data server (absolute, or relative to the page). By default, a local app serving the rows of x is started; view the table by printing the result.

times, cols, n

For a custom url: the date-time columns (names), optionally a summary of each column (a named list) to draw profiles and filter widgets, and the number of rows in the whole data (shown in the pager next to the count of a filtered view). The local app computes all three from the data.

name, ...

For the local app: its name and other arguments passed to xfun::new_app().

Value

x, with the data URL added.

Examples

if (interactive()) lt_serve(lt_viewer(iris))
